## 1. GPU in every process that draws

- Cause of the `metal_all=1` crash: no `.metallib` in the image; MetalPerformanceShaders aborts without its
  `default.metallib` (SpringBoard, through SiriUICore's blur). No mesh pipeline was ever requested.
- `userland-26/scripts/add-metallibs.sh` + `select-system-26.py` (`METALLIB`, `wanted_metallib`): 185 shader
  libraries in the sysroot; `prune-sysroot.py` made room (326 MB of Apple-only payload: `.hwx`, `Isp`, `Display`,
  `AGXMetalG17G.bundle`, `CameraEffectsKit`), reversible: `APPLE_ONLY=keep python3 scripts/prune-sysroot.py --restore`
  then `APPLE_ONLY=keep` for the selector. The user accepted the prune until plan B (docs/data-volume.md) grows the root.
- Plug-in patches (`kernel/drivers/gpu/userland/`): `HakiosMetalCA-metal-all-ui.patch` (`metal_all=1` = the processes
  that draw: /Applications, the user's containers, CoreServices apps, .appex, metal_test; `=2` every process),
  `HakiosMetalCA-refusal-detail.patch`, `HakiosMetalCA-wide-constants.patch` + `hakios-metal-wide-constants.patch` +
  `mesa/air-wide-constants-deferred-fetch.patch` (RenderBox's 128-bit `uint4 _shader_state` and its
  `[[color(fc_expr)]]` input). Plug-in 94d7ef1e in root 0393a6e7.
- Measured (gpu-ma1): SpringBoard on the GPU, no crash; Settings fully drawn within 7 s of the tap.

## 2. All apps on the home screen

- Root cause of the missing extensions (widgets, posters, Control Center controls): MobileGestalt answered
  `CPUArchitecture = arm64` (kernel cpu subtype `ARM64_V8`) so the `arm64e` capability was false and
  MobileInstallation refused all 356 app extensions ("Device capabilities do not match requirements: arm64e = 0").
  `kernel/patches/cpu-subtype-arm64e.patch` (in `patches/apply.sh`) + init26 `ls_reset=1` now also deletes
  MobileGestalt's cache (`/private/var/containers/Shared/SystemGroup/systemgroup.com.apple.mobilegestaltcache/...`).
- The 25-of-252 applications the scanner keeps: the kernel delivers all 254 entries (apfs_rdlog); the filter is in
  userland. `darwin-lisa/userland/tools/dirtest.c` (`build-dirtest.sh` -> sysroot `/usr/local/bin/dirtest`, NOT in
  root 0393a6e7 yet) checks readdir, getattrlistbulk and stat on /Applications from the phone:
  `init_run=/usr/local/bin/dirtest:/Applications`.

## 3. CPU frequency scaling

`kernel/drivers/cpufreq/README.md`: the governor follows each group's busiest core, up at once, down after three
quiet periods, never under a third of the top clock; `cpugov=0` turns it off. `cpugov_log=1` logs every change.

## How to continue

- Host run: `KERNEL=kernel-16k-consolidated-rc1.bak bash darwin-lisa/kernel/drivers/gpu/gpu-quietrun.sh TAG "EXTRA" "T1 T2"`
  (it brings the phone to the loader itself now); EXTRA is the standard host line of `logs/gpu-ma2-*` plus what the
  run tests; 460 characters in all. Every run ends in pmOS (`gpu-endrun.sh` then `bootos.sh pmos`, which gpu-quietrun's
  caller does).
- A new root: `scripts/add-metallibs.sh` is already applied to the sysroot; `FULL=1 bash scripts/mkimage-trim.sh`,
  rename by sha, `darwin-lisa/tools/flash-root.sh IMAGE`. Keep only the root on the phone, the previous good one and
  `6db16457`.
- A new kernel: edit under `darwin-lisa/kernel/...`, copy the driver into the tree with docker
  (`docker run --rm -v $M:$M darwin-lisa/unixnu-toolchain:latest cp SRC xnu-work/bsd/dev/...`; `patches/apply.sh` and
  the wires run from `.work/rebuild26.sh`), `sh darwin-lisa/.work/run-rebuild.sh`, grep the log for `error:`, check a
  new string in `kernel26.nopac`, back it up under a new name.
- A new vendor_boot: `KERNEL=... NAME=finalNN GEOMETRY= EXTRA_ARGS="..." bash darwin-lisa/loader/build-combined.sh`,
  then `darwin-lisa/tools/flash-vendorboot.sh out/vendor_boot-lisa-finalNN.img` (backs up the old one to `backups/`).
- Rollback: `tools/restore-safe.sh` (root 6db16457, vendor_boot 66c997f7), or `flash-vendorboot.sh` with the backup.

## Posters (2026-11-12, afternoon, host only): why PosterBoard's data store never opens, and the fix

Phone not touched. Cause, with the code path, in `docs/data-volume.md` section 5, "PosterBoard's data store". Short:
no syscall fails. PosterBoard's store viability check (`_PBFDetermineDataStoreViabilityForVersionWithinBaseURL`) wants
every store directory to read `NSURLFileProtectionKey = NSURLFileProtectionNone`; on the HFSX data volume
(`CONFIG_PROTECT 0`, no `MNT_CPROTECT`) CoreServicesInternal answers nil for class 0, so version 59 is never viable and
the 59 to 61 migration stops at its first step with no NSError ("Failed to migrate to Version 61 from 59", then "could
not initialize data store ... evades explanation"). `poster_seed=1` could not help (a 61 without its SQLite file and
with nil classes is not viable either) and is obsolete.

Fix: libdlisa in PosterBoard (`userland/inject/file-protection.c`, `fixPosterBoard` in `dlisa-inject.c`): a nil class
on a volume without `MNT_CPROTECT` reads as `NSURLFileProtectionNone` (`getResourceValue:forKey:error:` and
`resourceValuesForKeys:error:`). Kernel untouched. Host test: `sh userland/inject/test/run-tests.sh`.
